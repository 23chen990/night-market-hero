# 工厂看板 · PM 视角产品复盘 v1

> 撰写人：产品通 ｜ 评审对象：tools/board.*（妖怪夜市小游戏工厂的可视化看板）
> 评审日期：2026-09-01 ｜ 用户角色：产品经理（非工程师）

## 0. 一句话结论

看板的**信息架构**（"6 款游戏卡 + 内部迭代历史"）方向正确，但**实现层**有三类问题让它"看起来像半成品"：① 关键路径上仍残留工程师视角（英文/代码感）；② PM 真实工作流里的关键操作（废弃、记录验收意见、聚焦当前版本）缺失；③ 数据模型的边界没守住（内部实验混进游戏卡、原型 run 无流程记录、截图无节制）。

按 P0/P1/P2 分级后，本轮先收 P0。

---

## 1. 用户场景与核心任务

PM 在这个工厂里的日常循环：

1. **看**：进看板一眼看到 6 款游戏每款的状态（能不能玩、谁在弄、卡在哪）
2. **玩**：点开"当前可玩版本"在浏览器里跑一遍核心流程
3. **断**：判断是"通过 / 要改 / 错了"
4. **留痕**：把意见写下来交给工厂下一轮
5. **迭代**：工厂把意见消化，新版本出来后，"当前可玩版本"自动指向新 demo

对照现在的看板，**1 粗做、2 能做、3-5 几乎没做**。

## 2. 现状盘点（哪些做对了）

✅ **做对的事**

- 6 款游戏卡 + 清单驱动（`games.txt`），PM 拥有命名/归属的最终决定权
- 卡片级别的 PM 状态（✅可试玩验收 / ⏳等你拍板 / 🔧制作中 / ⛔卡住）
- "🎮 当前可玩"徽章区分"试玩版"和"内部记录"
- 流程上每步标了 agent + 模型（Sol/Terra/Luna/Spark）
- 截图当卡片封面
- "已迭代 N 次"取代了显眼的 ×N

## 3. 问题清单（按优先级）

### P0 · 阻塞 PM 实际工作（**本轮修复**）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| P0-1 | **原型类 run 打开后"制作流程"是空的** | `chart-demo`、`mobile-chart-adaptation` 这类没有 `state.json` 的研究/原型 run，点开只看到"立即试玩"和截图，流程区一片空白 | PM 看不到这条线是怎么出来的、谁做的、卡在哪；以为流程"坏了" |
| P0-2 | **没有废弃机制** | 6 款游戏里有的卡有 2-3 条 run，PM 试完旧的想标记"这条不要了"却没入口；只能忍 | 看板逐渐堆满废 run，"当前可玩"判断越来越不准 |
| P0-3 | **截图墙无节制** | `mobile-chart-adaptation` 有 113 张截图，详情页全展开一片红 | PM 想看核心画面得自己翻 113 张；信息过载等于没有信息 |

### P1 · 影响使用但非阻塞

| # | 问题 | 备注 |
|---|---|---|
| P1-1 | 英文/技术术语残留（"BLUEPRINT"、"playwright"、"vite"在证据里） | 大部分已映射，但 QA 报告等 JSON 里的原始字符串还在 |

## 4. 改进路线图

### Phase 1（本轮）· 收 P0

1. **原型类 run 流程视图**：无 `state.json` 时，展示"研究成果"——demo 入口、已生成的 artifacts、截图、workspace 内容，并显式标注"此为研究原型，未走完整流水线"
2. **废弃机制**：`games.txt` 支持 `游戏名 = -run-id1, run-id2, ...` 语法；废弃的 run 在卡片上有"已废弃"标记，不参与"当前可玩"评选，详情里默认折叠但可展开
3. **截图墙限额**：默认最多 6 张，超过的折叠到"查看全部 N 张"

### Phase 2（下次）· 收 P1

4. 隐藏非 PM 必需的技术字符串（QA/Build 报告里的 "vite:success"、"playwright:passed" 这类）
5. 详情页加"我玩完了 → ✅通过 / ❌要改 + 写一句"，意见写进 `tools/feedbacks/<run-id>.md`（PM 用纯文本，留痕最轻）
6. 副标题为空时显式提示"在 games.txt 加 `\| 一句话描述` 就能让 PM 视角更清楚"
7. "其他"加搜索/筛选，否则是死区

### Phase 3 · 体验优化

8. 搜索框（按游戏名/主题）
9. 时间排序（最新优先/最久未动）
10. "最近活动"流（这一周工厂做了什么）

---

## 5. 关键设计决策

- **不重写流水线，只在看板层加薄薄一层**。看板是只读视图，PM 写意见的入口也只是落到文本文件，不进任何数据库
- **PM 的"描述"和"验收意见"用纯文本**，不引入新的 Schema/JSON。PM 不该被格式束缚
- **废弃是软删除**：run 目录不删，标记 + 折叠，未来可恢复
- **"当前可玩"只看活跃 run**：被废弃的不参与评选，避免"已废弃的旧 demo"霸占按钮
