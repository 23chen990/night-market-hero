# 《夜市飞侠》V2：载具争夺与自然试玩实施交接

> 状态：**开发候选（Draft）**，不是商业发布通过。默认可玩入口仍为 `index.html → src/main.ts`，手机横屏一根手指按住／松手。**不得创建与原游戏平行的 DEMO**。
>
> 代码基线：`9608d55dd5e246641b86352f534e3329427b5b3a`（旧修复分支最后一次双 Job 成功的工程与浏览器基线）；V2 在独立 PR 上继续。本文件与同 PR 的代码和测试一起审查。

## 一、这次已经改变的玩家规则

玩家不再因为“进入第 N 段”自动得到载具，也不会因为飞过一个高度跟随角色的巨型光环而获得载具。

- **获得机会，不保证奖励**：第 2、4、6、8 段分别安排滑索、纸鸢、灯笼、青鸾的真实世界物件，后段仍按确定性种子投放；每个挂环始终定位在建筑、横梁或绳索的源图支撑点附近。
- **四类操作**：滑索＝离开旧飞索、正确时机松手接吊轮；纸鸢＝高空松手；灯笼＝经过灯绳结附近按住；青鸾＝此前 10 秒内两次真实漂亮松手 + 高空松手接住。
- **碰撞精确对应可见形象**：高速扫掠椭圆，边缘不透明暗箱不存在。玩家需要实际飞进画出的有效挂环；放弃高线可以安全错过。
- **不再储存隐形载具**：已有载具期间遭遇下一件不会排队自动补发；旧存档的历史 `vehicleQueue` 恢复时清空，不退款、不自动乘骑；经济和角色存档数据保持原样。
- **实例级事件**：`instanceId=seed:segment:chunk:type`，每个遭遇最多一次 `claimed|missed`，不能把本局两次遇到同一种载具、一次领取一次错过合并成矛盾结论。
- **结果可归因**：错过包含“不够高”“松手时机不对”“按住接灯绳”“正在乘坐其他载具”等原因；成功能看到载具名称与按住／松手操作，动作漂亮时有一次性额外 +8。

## 二、首次遭遇的四种具体配置

| 顺序 | 遭遇目标 | 逻辑入口 | 玩家应感知到 | 难度原则 |
| --- | --- | --- | --- | --- |
| 1 | 货运滑索 | `release` + 世界物件椭圆碰撞 | 提前看到吊轮，松开绳索飞入挂环，立刻滑行 | 允许新手通过一次正确松手获得，不是自动发放 |
| 2 | 纸鸢 | `high-release` + 高度门槛 + 椭圆 | 需要提前走高挂点，飞入鸢绳柄，借高线滑翔 | 普通低线可以顺利绕过，不会白送 |
| 3 | 灯笼群 | `press`（新按下边沿）+ 椭圆 | 飞到灯绳结、按住接绳；仍保留原有单指控制 | 追兵临近也必须真实按住，不能穿越后自动拿到 |
| 4 | 青鸾 | `stylish-release` + 两次漂亮飞索动作 + 椭圆 | 高空可见召唤物，完成条件才能握住 | 稀有、可错过；不能拿概率替代操作难度 |

设计成功率**只作后续用户测试目标**，非测得结果：滑索 70–85%、纸鸢 45–65%、灯笼 35–55%、青鸾 15–30%。先保证“可理解、可尝试、可错过”，再调玩家样本成功率。不能把抽样预期冒充当前达成的量化指标。

## 2026-10-14 纸鸢再现的物理时窗问题

在 GitHub CI `c018947` 真实 844×390 触控证据中，技巧输入已真实松手并经过纸鸢可见椭圆（最近位置 x=8046.8，y=459.8；纸鸢中心 x=8044.3，y=510.7）。但从高屋檐松手到物件接触的自然飞行时长超过此前硬编码 `releaseAge <= 65 ticks`（0.54秒），因此被错误提示“松手时机不对”。固定物件坐标与碰撞椭圆均未更改。本轮将纸鸢高空释放最长飞行窗口调至 130 个 120Hz 物理 tick（1.08 秒），保留“真实释放／不可挂着绳／必须碰到可见目标／高度／水平速度”的全部条件，并新增时窗上下边界断言。自然输入脚本也保存每次实际按下/松开 tick，由同 SHA 对照门禁检查成功接触前是否有真实最近松手动作。

注意：这是**物理时窗调参**，仍需下一次 CI 验证自然路线。对于 IAA、真人、真机和另两种高阶载具，继续维持 BLOCKED。工程工件已移除完整仓库源码 tar（仅文件图片即 >800 MB），Git SHA 足以追溯代码；保留构建 HTML 与 sha256，避免无意义巨型工件。
