# 《夜市飞侠》V2：载具争夺与自然试玩实施交接

> 状态：**开发候选（Draft）**，不是商业发布通过。默认可玩入口仍为 `index.html → src/main.ts`，手机横屏一根手指按住／松手。**不得创建与原游戏平行的 DEMO**。
>
> 代码基线：`9608d55dd5e246641b86352f534e3329427b5b3a`（旧修复分支最后一次双 Job 成功的工程与浏览器基线）；V2 在独立 PR 上继续。本文件与同 PR 的代码和测试一起审查。

## 一、这次已经改变的玩家规则

玩家不再因为“进入第 N 段”自动得到载具，也不会因为飞过一个高度跟随角色的巨型光环而获得载具。

- **获得机会，不保证奖励**：第 2、4、6、8 段分别安排滑索、纸鸢、灯笼、青鸾的真实世界物件，后段仍按确定性种子投放；每个挂环始终定位在建筑、横梁或绳索的源图支撑点附近。
- **四类操作**：滑索＝离开旧飞索、正确时机松手接吊轮；纸鸢＝高空松手；灯笼＝经过灯绳结附近按住；青鸾＝此前 10 秒内两次真实漂亮松手 + 高空松手接住。
- **碰撞精确对应可见形象**：高速扫掠椭圆，边缘不透明暗箱不存在。玩家需要实际飞进画出的有效挂环；放弃高线可以安全错过。
- **不再储存隐形载具**：已有载具期间遭遇下一件不会排队自动补发；旧存档的历史 `vehicleQueue` 恢复时清空，不退款、不自动乘骑；经济和角色存档数据保持原样。
- **实例级事件**：`instanceId=seed:segment:chunk:type`，每个遭遇最多一次 `claimed|missed`，不能把本局两次遇到同一种载具、一次领取一次错过合并成矛盾结论。
- **结果可归因**：错过包含“不够高”“松手时机不对”“按住接灯绳”“正在乘坐其他载具”等原因；成功能看到载具名称与按住／松手操作，动作漂亮时有一次性额外 +8。

## 二、首次遭遇的四种具体配置

| 顺序 | 遭遇目标 | 逻辑入口 | 玩家应感知到 | 难度原则 |
| --- | --- | --- | --- | --- |
| 1 | 货运滑索 | `release` + 世界物件椭圆碰撞 | 提前看到吊轮，松开绳索飞入挂环，立刻滑行 | 允许新手通过一次正确松手获得，不是自动发放 |
| 2 | 纸鸢 | `high-release` + 高度门槛 + 椭圆 | 需要提前走高挂点，飞入鸢绳柄，借高线滑翔 | 普通低线可以顺利绕过，不会白送 |
| 3 | 灯笼群 | `press`（新按下边沿）+ 椭圆 | 飞到灯绳结、按住接绳；仍保留原有单指控制 | 追兵临近也必须真实按住，不能穿越后自动拿到 |
| 4 | 青鸾 | `stylish-release` + 两次漂亮飞索动作 + 椭圆 | 高空可见召唤物，完成条件才能握住 | 稀有、可错过；不能拿概率替代操作难度 |

设计成功率**只作后续用户测试目标**，非测得结果：滑索 70–85%、纸鸢 45–65%、灯笼 35–55%、青鸾 15–30%。先保证“可理解、可尝试、可错过”，再调玩家样本成功率。不能把抽样预期冒充当前达成的量化指标。

## 三、文件职责和不得绕开的约束

| 文件 | 本轮具体职责 |
| --- | --- |
| `src/vehicle-encounters.ts` | 固定来源、实例身份、可见椭圆、不同动作的纯逻辑；**这是新的纯函数模块，不拥有第二份 runtime 状态** |
| `src/game-core.ts` | 实际 120Hz 游戏状态、合法获取、错过、实例事件、旧档兼容和物理；与以前的追捕、连击、结算共用状态 |
| `src/ride-renderer.ts` | 真实世界支撑到挂环的可视连接，四种不同实体；绘图边缘必须对应碰撞半径 |
| `src/experience-director.ts` | 前期机会表、靠近提示、高低线判断；不要读取用户玩法以动态跟随放置奖励 |
| `src/experience-hud.ts` | 成功、失败、品质奖励的短反馈；不写钱包，不能伪造广告成功 |
| `src/run-snapshot.ts` | 老版兼容、新实例字段校验，恶意/损坏数据拒绝恢复，避免多次同一奖励 |
| `tests/vehicle-encounters-v2.test.ts` | 固定支撑来源、动作门槛、同实例只能结算一次、旧档字段合法性 |
| `tests/v2-player-choice-contract.test.ts` | 用真实 `act('press'/'release')` 触发四种规则；只用测试物理状态定位到验收起点，**不冒充自然人通关** |
| `tests/v2-natural-input-browser.ts` | Chromium 实际触屏/键盘/可见按钮；读状态辅助操作，自动录屏和记录每个实例真实结果 |
| `tests/v2-compare-gate.mjs` | 同构建、同窗口、同种子对照“常规路线 vs 主动松手”；不能独自签署感知或真机验收 |

**禁止**：把挂环移到角色实时高度、扩大隐形拾取框、进入段直接发载具、在后台待领队列存起来、让测试代理调用 setPlayerForTest 冒充自然试玩、删除失败断言换绿色、改变原经济原子事务、为了看见玩法恢复旧的全屏不透明地图补丁。

## 四、当前已证明和未证明的事

### 已有工程证据

- `npm run lint`、`npm run typecheck`、`npm run build` 与完整 `node --import tsx --test tests/*.test.ts` 已在工作副本通过；完整测试中的历史跳过项继续明确标记。
- 逻辑级别：四种载具均存在实体支撑、碰撞与动作门槛；可以主动错过、同一实例无法二次结算、不同实例可以不同结果；载具排队不再有隐式授予，旧档迁移有测试。
- Chromium 的受限环境已通过 `document.write` 加载完整构建和真实触控／键盘事件；**此模式用的是内存 localStorage 桥，仅用于动作视觉观察，不可替代 `file://` 开箱、浏览器存档和第三方发布验证**。
- 同一个 844×390 浏览器、相同种子 32 的两种自然输入路线：普通路线错过第一个滑索，有意识在真实挂点松手的路线拿到滑索且能操作。纸鸢仍会被错过，不能把「四种载具都已自然成功拿到」写成已证事实。

### 仍须 Codex／独立 QA 完成

1. 用**可见操作、不改物理状态**的浏览器路线演示纸鸢、灯笼群和青鸾各一次成功和一次主动错过，完整录屏并检查玩家是否真看得懂。若无法真实接近，修固定线路上的可见挂点或动作窗口，不得恢复自适应奖励。
2. 动态地图接缝 QA：所有过渡点从右到左跨过整屏的连续录像，检查屋檐、栏杆及颜色结构，而非只测单帧截图。
3. 真机横屏的镜头舒适性（包括 60Hz/120Hz、低端机）、操作触点可达性、视觉遮挡、官兵危险提示是否真正看得见。自动驾驶无法替代真实盲测。
4. 实际体验前 60–90 秒的玩家测试：教学通过时间、第一次主动抢滑索、被抓原因、错过后的再尝试意愿；先调整引导，再调整碰撞阈值。
5. 整局复核：继续收工、任务、钱包、角色购买、重新开始、旧存档恢复、失败复起、离线单 HTML、微信/抖音/TapTap 平台包。后面的平台验收不得用 Web 通过替代。

## 五、建议本 PR 验收门槛

- **工程正确性**：Node 22、lint/typecheck/build、全部单测；不得删除历史契约；HTML 构建哈希与录像一致。
- **自然动作因果**：同一设备和种子，常规按住／松手能错过，掌握挂点/松手时机则能获得第一件载具；随后至少证明另两种主动成功路径，最后四种都要有可重现的成功和错过证据。
- **体验感知**：新人能读懂“在哪里、什么时候、为什么错过”，普通飞索路线继续可活，追兵有真实逼近和反制，接缝动态没有明显结构断裂，HUD 不遮住主要角色和挂点。
- **生命周期**：正常一局的暂停／存档／主动收工／领奖／再来一次、新旧档不重复发钱、不丢掉角色。
- **发布分层**：Web H5 工程及操作门槛与真人体验门槛分别记状态。真实手机/宿主/广告缺证据时商业发布保持 BLOCKED。
