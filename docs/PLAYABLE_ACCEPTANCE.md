# 夜市飞侠：可玩升级验收与开发交接

## 1. 当前结论如何核验

本轮基于 `b41dc1eb50994cab498ccc979555bd7960478ff2` 修改实际默认入口，不是另做一个演示页面。玩家流程与后续开发约束见根目录 `PLAYABLE_START_HERE.md` 和 `AGENTS.md`。

**最终通过结论必须同时满足当前构建哈希、实际执行结果和画面审查。** 当前材料应位于 `evidence/playable-upgrade-20261012/`，其中：

- `runtime-product-gate.json`：构建、静态检查、完整回归与单文件启动。
- `qa-natural-journey-report.json`、`journeys.json`：真实浏览器时钟下的触控/键盘旅程及输入日志。
- `safety.json`：真实失败、免费复起、旋转屏幕暂停、再次失败与重开。
- `perceptual-qa-report.json`：对应构建截图的视觉审查范围和限制。
- `*.png`：原始浏览器画面；`checks/`：执行日志；`manifest.sha256`：文件校验。

缺少这些材料、报告失败或当前 `dist/index.html` 与报告哈希不符，都不能称为当前版本通过。`npm run verify:release` 会先重建，再以严格模式退出；不能用旧 dist 绕过检查。该命令只验收浏览器可玩版本，输出中的 `commercialReleasePassed` 必须保持 `false`，直至另行完成真实平台发布验收。

## 2. 为什么以前“有玩法却玩不到”

| 原因 | 本轮实际修改 |
| --- | --- |
| 载具依赖随机抽取、部分内容很靠后 | 前段第 2/4/6/8 个地图段固定遇到滑索、纸鸢、灯笼、青鸾；后续保留种子变化 |
| 载具主要存在于物理状态，没有各自清晰形象 | 实际渲染四种载具，并显示操作方式、名称与倒计时 |
| 切换小段会清除或覆盖未结束的载具 | 挂载跨段保留，后续遭遇进入有界队列 |
| 载具进入时继承旧输入或坠落速度 | 滑索增加短暂输入交接保护；新载具接住角色；结束后给重新挂接窗口 |
| 青鸾升力失控或晚按时无法及时挽救俯冲 | 限制升力/高度；一次真实振翅立即制动下坠，持续按住继续拉升；不输入仍可失败 |
| 教学失误让玩家在接触主要内容前反复退出 | 启动前暂停，实时提示松手时机，迟到/反向松手提供有限恢复；辅助不伪造连击 |
| 连击、里程、道具结果被隐藏界面吞掉 | 游玩中的可见读数、奖励提示、道具成功/不可用反馈与音效开关 |
| 有任务和角色数据，但实际结算链条不突出 | 暂停可主动收工；结算可领取达成任务；首个替代角色调到 600 金币；下一程实际使用所选角色 |
| 某些复起资格取决于当前地图小段完成度 | 按本局真实资格与经济事务判断，不再因跨段突然改变 |
| 成长菜单在手机上挤掉返回按钮，叠加旧暂停层 | 固定头部和返回区，仅内容滚动；终态/成长对话框不显示重复暂停层 |
| 下载 HTML 一改名就跳转失败 | 构建移除源码辅助跳转；验证移到空目录、改名、离线打开 |

开放街区模式中的旧闭门闯关、旧棚顶坍塌碰撞没有偷偷恢复。它们不是“本轮已经做成默认玩法”的内容。这样避免用不可见碰撞和互相冲突的模式制造假丰富。

## 3. 玩家应该实际经历的一局

点开始后，按住抓钩，角色向前摆过挂点时松手，再按住接下一个。金币存在高低两条空间路线：高线奖励更高，低线缓解追兵；连飞影响奖励倍率。

进入夜巡后，早期四种载具的操作分别为：滑索按住加速、松手弹射；纸鸢按住拉升、松手滑翔；灯笼按住建立挂点、松手向前飞；青鸾按住振翅、松手俯冲。载具期间仍需要操作，不是自动播放过场。出现的具体秒数随玩家速度变化，不承诺每位玩家同一秒触发。

可以继续挑战，也可以暂停后收工。结算后领取已达成任务，用实际钱包解锁、选择角色，再来一局。刷新不能重复获得金币或任务奖励。失败后符合条件可使用当天免费复起，再次失败不再显示第二次免费或伪造广告复起。

## 4. 验收方法与不能冒充的证据

`tests/playable-browser-audit.ts` 从实际 `dist/index.html` 启动，以 844×390 触控和 1280×720 键盘两种配置运行。读取游戏状态帮助自动玩家决策，但动作仅通过浏览器真实触控事件、键盘与可见按钮产生。没有调用游戏的 `act/step/advanceTicks/setPlayerForTest/loadScenario` 去生成所谓自然试玩。

通过条件包括：启动卡不耗时、正常完成教学、遇到四种载具且每种可观察至少 120 个模拟 tick、自然经过四处屋顶交界、仍能控制角色、暂停清输入并冻结、刷新精确恢复、主动收工、领取任务、再次刷新不重复结算、正常购买角色并在下一局使用。成长菜单的返回按钮还要实际落在可见屏幕内。

`tests/playable-safety-audit.ts` 故意停止输入形成真实失败，实际点击免费复起，再测试竖屏冻结、恢复、第二次失败与重开。`tests/file-launch-smoke.ts` 使用 WebKit，验证原文件和空目录内改名文件都可启动且不请求远程依赖。

截图操作不应让自动玩家长时间停止操控；但不得因此调用快进、瞬移或篡改状态。测试选择器必须指向可见实际控件，不能误点隐藏的历史重复按钮。

**这些是状态辅助的自动化功能/视觉证据，不是陌生用户盲测。** 它们不能证明留存率、广告收益、所有玩家都能通关，也不代替手机实机性能验收。

## 5. 本轮发现问题后继续修复的记录

浏览器实际复测发现并修复了单元测试未先发现的：滑索一帧退出、低空灯笼换乘坠落、青鸾晚按回升滞后、复起资格随小段变化、成长菜单返回不可见和暂停层叠加。

也修正了测试工具自身的问题：截图时停止输入造成坠落、在暂停前先释放造成俯冲、选择器匹配到隐藏重复暂停按钮。这类失败只允许修正驱动器和选择器，不能删除四种载具、自然经过接缝、存档恢复和结算防重等通过条件。

单测保留旧闸门与旧三关旅程的历史跳过；本轮新增回归不得新增跳过。角色降价只更新对应价格断言，保留购买原子性、重复购买不扣款、选角持久化、任务重复领取、存储失败、复起/结算防重等检查。

## 6. 复现命令与后续工作顺序

```sh
npm ci
npm run check
npx playwright install --with-deps chromium webkit
npm run test:file
npm run test:play
npm run test:safety
npm run verify:release
```

使用 Node 22 与仓库锁文件。浏览器受本地策略限制时，使用仓库现有 Actions 获取真实日志和截图，不要把旧的本机阻塞当作永远无法验收的理由，也不能冒充执行成功。

下一阶段先做真正手机与陌生玩家观察：是否读得懂抓钩节奏、第一局何时失败、能否区分四种载具、是否理解收工与角色成长。再依据观察调整数值和密度，不优先堆叠新玩法。

## 7. 仍独立阻塞的商业发布范围

微信、抖音与 TapTap 的包体、宿主环境、平台适配/工具链、真实广告、设备表现及审核材料并未由本轮浏览器 QA 证明完成。当前独立 HTML 不是三平台已验证的原生小游戏包，不能只补 AppID 就声称发布完成。

地图结论只覆盖当前构建被实际查看的屋顶/高塔交界和屏幕尺寸，不扩展为所有种子、所有分辨率、所有长局都无瑕疵。独立文件包含内联资源，商用阶段仍需在真实目标设备上验证加载耗时、内存、帧率与包体策略。
