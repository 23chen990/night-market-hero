## 验证方式与证据

构建采用 Node 22、仓库锁文件；Chromium 使用锁定 Playwright 对应的 `153.0.8010.12`，离线启动另用 WebKit。所有最终报告都记录实际 HTML 的 SHA-256，不将旧版本截图重标为本轮通过。

- `npm run check`：465 个用例，455 通过、0 失败，10 个既有历史兼容跳过；包含 lint、TypeScript 和构建。
- `npm run test:input`：7/7 通过。真实键盘、CDP 触控取消、窗口旋转与显式标注的 blur 事件故障注入；读取状态用于断言，没有写入游戏状态。
- `npm run test:ads`：8/8 通过。自然按钮和真实时钟，使用明确标注的模拟 SDK 回调验证 complete、dismissed、广告切回、缺失 provider，以及旋屏完成、取消后重试。它证明应用层处理，不证明第三方真实广告接入。
- `npm run test:play`：844×390 触控与 1280×720 键盘，教学、夜巡、四种遭遇、收工、任务、角色、重开与重新加载；自动玩家通过只读状态决定真实输入。
- `npm run test:pursuit` 与 `npm run verify:chase-matrix`：同一构建比较可逃脱旅程和故意失误被实际官兵接触捕获。
- 四路线 `v2-natural-input-browser.ts` 对照：普通、技巧、灯笼和青鸾；分别经三道独立门禁检查真实领取与错过。具体时长、骑乘和输入事件保留在报告中。
- `npm run test:file`：原文件及复制到空目录后改名文件的离线打开。
- `npm run test:safety`、`test:coach` 和 `playable-menu-audit.ts`：失败、复起、重试、旋屏、四尺寸操作提示及菜单。

当前最终汇总以 [`checks/`](../evidence/optimization-20261024/checks/) 和 [`manifest.json`](../evidence/optimization-20261024/manifest.json) 为准。早期候选和旧版故障诊断保留各自指纹，不作为最终构建的通过证据。

最终三道载具门禁分别为 `ENGINEERING_CONTRAST_PASS`、`LANTERN_REAL_TOUCH_PASS`、`BIRD_NATURAL_INPUT_PASS`。同一青鸾实例在灯笼路线中错过，在青鸾技巧路线于 tick 3676 获得，先前两次真实漂亮松手为 3553/3675；持续观察骑乘 1426 tick。完整自然旅程中的灯笼分别持续观察 527、581 tick（约 4.39、4.84 秒）。这些数值来自当前构建的真实浏览器输入，不是把状态改成“已获得”。

灯笼专项驾驶器出现过两次失败：原策略在强上升时提前松手，预测窄带尝试又覆盖通用退出条件而死抱旧绳。最终删掉该附绳覆盖，恢复原有通用摆荡松手、倒摆和最长持绳退出；仅在真实离绳后按原实体椭圆选择新 press。产品拾取窗口、碰撞半径、三个比较门禁均保留；失败轨迹和诊断仍在 `player-choice-diagnostics/`，最终一次针对性自然输入验证通过。

## 后续仍需验证的体验问题

1. **真人首次游玩与复玩意愿**：自动玩家看状态决策，能证明输入路线存在，但不能证明第一次玩的人能读懂、觉得公平或愿意再来一局。应优先实测首次 30 秒与 90 秒，而不是继续添加玩法。
2. **实体手机性能与地图动态观感**：本轮检查四尺寸截图和现有接缝采样，连续镜头的主观连贯、角色辨识度及低端手机 FPS 仍需实体设备观察。试玩 HTML 约 33.4 MiB，平台包体方案需要单独评估。
3. **真实宿主与广告**：本轮完成应用侧暂停、回调和复起治理；TapTap、微信、抖音的实际广告位、宿主生命周期和发布包仍需要各自环境验证。`commercialReleasePassed` 保持 `false`。

本轮代码与证据随独立变更交付，目标分支为 `feat/v2-retry-goals-20261016`，保持 Draft，不合并 main 或部署。下一轮应围绕以上观察结果调整难度、画面辨识和资源加载。新增生命周期测试已加入项目浏览器 CI 配置；上文列出的通过结果来自本地实际执行，远程 CI 结果以对应提交的 Actions 记录为准。
