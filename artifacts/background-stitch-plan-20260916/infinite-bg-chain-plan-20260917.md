# 无限地图背景·链式生产与多平台发布计划（2026-09-17）

> 本计划是当前唯一有效的背景资产生产与发布计划。
> **取代**：① `asset-spec-master-20260917.md` 中的「12 张桥接图」交付方案；② `market-loop-pilot-handoff-prompt-20260917.md` 的「环方案」试点提示词。两文档中的画风锚点、承重规范、尺寸规格继续有效，冲突处以本计划为准。

---

## 1. 一页结论

| 项 | 决定 |
|---|---|
| 架构 | **链式无限地图**（不闭合；链尾与下一条链在换区点暗角相接） |
| 规模 | **10 条链 × 10 张 = 100 张**（含已有试点 4 张，新产 96 张） |
| 生成方式 | **10 轮 × 每轮 10 张**（轮次制，每轮验收通过再开下一轮） |
| 交付格式 | 出图 AI 交 PNG 原图；入库转 **JPEG q85**（单张 ≤350KB，全量 ≈25–30MB） |
| 平台策略 | web 类（233/海外）全量打包+懒加载；**微信/抖音小游戏的背景图全部走 CDN 远程加载，不占包体** |
| 玩家体验 | 100 张独特屏 ≈ 2.5–3.5 分钟不重复 + 换区随机切链，正常一局无重复感 |

## 2. 架构：为什么是「链」不是「环」

1. 环的闭合张需双参考（上一张右缘 + 第一张左缘）——试点唯一结构瑕疵（A3→A4 齐切飞檐）正出在闭合张上；
2. 闭合缝每 12–16 秒周期性出现，是常驻风险；
3. 环长被累积漂移锁死在 6–8 张。

链方案：每张只参考上一张右缘（单参考，试点实测相关 0.948 的近完美缝即单参考成果）；链首尾**永不相邻**，漂移无害；链可做长（10 张/条）；后续加链零耦合。

**运行时行为**：
- 链内 10 张连续无缝滚动；
- 换区（闹市→屋脊→水市循环）发生在链尾：链尾右缘暗角 → 下一条链头左缘暗角，夜色中自然过渡；
- 选链规则：`seed + district + visitIndex` 确定性 + 未用链优先的洗牌，同一玩家不连刷同一条链。

## 4. 资产规格

- **尺寸**：1672 × 941（工具受限时保持该比例并尽量高清，入库统一缩放）；
- **格式**：出图 AI 交付 **PNG 原图**（完全无透明）；入库时转 JPEG 质量 85；
- **命名**：`<flavor>-c<链号>-t<两位序号>.png`，如 `market-c2-t01.png`、`waterfront-c3-t10.png`；
- **暗角规则**：每条链 **t01 左缘 ~160px** 与 **t10 右缘 ~160px** 天然收暗、结构简化（无半截悬空结构）；链中间各张正常衔接；
- **画风锚点**：`src/assets/night-city/` 现有 6 张全景图。冷蓝青雾夜：平均色 R 10–16 / G 22–29 / B 26–38，不透明区亮度 0.08–0.11；暖黄点缀仅灯笼窗光；剪影禁止死黑（亮度 ≥0.03）；
- **承重规范**：檐必有柱、棚必落地、桥必有墩、灯笼必挂锚点（同总规范文档第三节，继续有效）。

## 5. 平台发布矩阵（限制已核实，2026-09）

| 平台 | 形态 | 包体限制 | 背景资产策略 |
|---|---|---|---|
| 233工坊 | web zip | 宽松 | 全量打包（JPEG，~30MB），首屏只加载当前链 |
| 海外 web（CrazyGames/Poki 等） | web | 无硬限制，重首屏速度 | 全量打包 + 按链懒加载 + 预取相邻链 |
| 微信小游戏 | 小游戏 | **主包 ≤4MB；主+分包合计 ≤30MB** | 代码进主包/分包；**背景图全部走 CDN**（HTTPS 合法域名），按链懒加载 |
| 抖音小游戏 | 小游戏 | **主包 ≤4MB；总包 ≤20MB** | 同微信：背景走 CDN/远程包 |
| TapTap | 页面/客户端 | 宽松 | 全量打包或 CDN 均可 |

**结论**：100 张 JPEG ≈ 25–30MB，塞不进抖音 20MB 总包、塞进微信 30MB 也没给代码留空间 → **小游戏平台一律远程加载背景**，web 平台打包但必须懒加载（首屏只拉当前链 ≈3MB，后台预取下一条）。

> 备注：微信/抖音小游戏还需 Phaser 小游戏适配层（weapp-adapter 类）与平台账号/域名配置，属**独立工程任务**，不在本资产计划内，建议背景链跑通后单独立项。

## 6. 生产工作流（轮次制，防级联返工）

| 轮次 | 生成内容 | 参考对象 |
|---|---|---|
| 第 1 轮 | 9 条新链的 t01（链头）+ market-c1-t05 | 链头：对应风味的现有全景图作风格参考；c1-t05：试点 A4 右缘 |
| 第 2–6 轮 | market-c1 的 t06–t10 + 9 条链各自下一张 | 各链上一张的右缘 |
| 第 7–10 轮 | 9 条链的 t07–t10 | 同上（t10 记得右缘做暗角） |

- 每轮 10 张（第 7–10 轮为 9 张），共 96 张新图；
- **每一轮交付后先验收（我做，指标见下），通过才开下一轮**——因为第 N 张出错会级联污染后续所有参考，必须前置拦截；
- **传输方式**：每轮一个文件夹或 zip（`round-01.zip`…），附清单（文件名 + 所属链 + 参考了谁的右缘）。禁止聊天逐张粘贴（已出过重复上传、缺图、只有 JPG 三种事故）。

## 7. 验收标准（每轮自动执行）

| 指标 | 阈值 | 方法 |
|---|---|---|
| 接缝两侧亮度剖面相关性 | ≥ 0.70 | 逐行边缘色差脚本（已就绪） |
| 接缝亮度台阶 | \|台阶\| ≤ 5 | 同上 |
| 结构连续 | 人工看合成特写 | 「上一张右缘 \| 新图左缘」拼接图 |
| 色彩基准 | 平均色落在 R10–16/G22–29/B26–38 区间 ±20% | 批量统计脚本（已就绪） |
| 轻微亮度台阶（≤8） | v3 边缘校准兜底 | 不透明调色，已验证方案 |

不合格单张：**从该张起该链后续作废重出**（级联规则），所以验收必须逐轮把关。

## 8. 工程接入里程碑（资产到位后，我来做）

1. **入库脚本**：PNG→JPEG q85 转换、SHA-256 登记、生成链清单 JSON（链-风味-张序-文件映射）；
2. **renderer 改造**（只动 `night-city-renderer.ts` + 新增链调度模块，不碰 `district-world.ts` 玩法调度）：区→链映射、`seed+district+visitIndex` 确定性选链、链内连续滚动、链尾暗角交接；
3. **懒加载**：首屏当前链，后台预取下一条链（web 与小游戏通用）；
4. **平台打包**：web zip（233/海外）+ 小游戏远程资产清单（CDN 路径表）；
5. **全量验证**：typecheck / lint / build / 全量测试 + 844×390 与 1180×720 自然流程截图（重点看链尾交接与链内接缝）。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 出图质量波动 | 轮次制+逐轮验收，坏张当轮拦截，不级联 |
| 包体积超限 | JPEG q85 + 小游戏走 CDN + web 懒加载 |
| 传输事故（重复/缺图/JPG） | zip/文件夹 + 清单核对（文件数、尺寸、哈希查重） |
| 试点 4 张只有 JPG 副本 | 用户从出图工具重新导出 PNG 原图（与后续轮次一起给即可） |
| 微信/抖音适配层工作量 | 独立立项，不阻塞背景资产生产 |
